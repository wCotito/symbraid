## Безопасность и совместимость

Публикуемые минимальные версии MCP, PyJWT и urllib3 защищают также pip, pipx
и `uv tool install`, которые не используют репозиторный `uv.lock`. Python 3.10,
остальные зафиксированные версии и платформенные ветки сохраняются.

HTTP-аутентификация сравнивает непрозрачные bearer-токены за постоянное время
и не включает JWT-аутентификацию SDK. Проблема PyJWT является риском транзитивной
зависимости, а не свидетельством обхода bearer-проверки. Регрессия проверяет
отклонение поддельных HMAC-подписей с CR-only PEM и PEM с отступом; обычные
RSA-подписи остаются корректными.

MCP сохраняет stateful-режим. SDK 1.30 ограничивает число сессий и освобождает
завершённые. Приложение проверяется с лимитом в две сессии: превышение возвращает
503, DELETE освобождает место, удалённый ID возвращает 404. Проверки bearer,
origin, размера запроса, read-only tools и изоляции проектов сохраняются.

vsce 4 требует Node.js 22.12.0+ для разработки и сборки: ранние версии Node.js 22
не загружают его ESM-зависимости через синхронный `require()`. CI проверяет точный
минимум и последнюю версию Node.js 22. Оба установщика проверяют
версию перед сборкой; пропуск расширения не требует Node.js. VS Code 1.90
остаётся поддерживаемым. Зависимости сборки исключены из VSIX.

## Проверка и закрытие

Security workflow проверяет все Python-варианты и extras через временный
экспорт PEP 751 и `pip-audit==2.10.1` с OSV, а также весь npm lock-файл.
Уязвимости и ошибки сервиса приводят к неуспеху задания. Проверки core,
транспортов MCP, расширения, браузера, документации и артефактов остаются
условиями приёмки релиза.

GitHub закрывает алерты после попадания исправленного графа в default branch
и обработки Dependabot. Зелёный патч или pull request означает подготовленное
исправление и не утверждает, что GitHub уже закрыл алерты.
