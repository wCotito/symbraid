# Интеграция VS Code

Расширение VS Code — тонкий клиент в пределах открытого workspace. Оно запускает
и останавливает watcher ядра Symbraid и показывает состояние и настройки, но не
владеет индексацией, embeddings, базами данных или миграциями.

## Граница workspace

Наблюдается только текущий workspace. Расширение не должно сканировать чужую
директорию, смешивать проекты или изменять внешнюю коллекцию. Ядро остаётся
источником истины для одного активного managed source и impact plan миграции.

## Настройка

Установите artifact из `extensions/vscode-symbraid`. Параметр
`symbraid.executablePath` задавайте только тогда, когда команда `symbraid`
отсутствует в `PATH`; пустое значение разрешает её через `PATH`. Не храните
credentials в settings или workspace-файлах.

Открытие директории в VS Code или просмотр Manage только читает настройки.
Для незарегистрированной директории Manage показывает глобальные параметры
хранилища и embedding, не создавая проект, source, индекс или watcher.

Чтобы включить новый проект с глобальными настройками, нажмите иконку строки
состояния. Другой вариант — открыть Manage > Проект: поля уже заполнены
глобальными значениями. Оставьте их или измените backend, расположение хранилища
и модель, нажмите **Зарегистрировать и запустить**, проверьте план и подтвердите.
Регистрация сразу создаёт первый managed source с выбранными настройками и
включает auto-watch. Отмена плана или подтверждения оставляет директорию
незарегистрированной.

Каждая регистрация получает уникальное расположение managed-хранилища. Повторная
регистрация после удаления записи проекта сохраняет старый индекс и создаёт новый.
План также фиксирует провайдера embedding, модель, размерность, endpoint и ссылку
на учётные данные: при изменении профиля перед регистрацией нужен новый план.

Для глобальных настроек доступны глобальные профили embedding. Профиль проекта
можно явно выбрать только для его владельца, в том числе при регистрации.

Повторное открытие существующего проекта сохраняет активный source, локальные
переопределения и настройку auto-watch. Включённое автонаблюдение возобновляется.

Если настройки проекта недоступны, Manage отдельно пытается загрузить
глобальные настройки и глобальные профили моделей, а ошибку проекта показывает
на вкладке «Обзор».

Для этого сценария обновите ядро и расширение VS Code: ядро предоставляет
предварительные настройки без регистрации и проверяет план регистрации.

Команды Manage и watcher показывают человекочитаемый статус. Для индексации,
смены backend и восстановления используйте [CLI](../cli.md) и
[развёртывание агентом](../operations/agent-deployment.md).

Вкладка «Обзор» в Manage отображает актуальный ответ CLI
`project.index_status`: полноту индекса, счётчики, активный backend и владельца
watcher.

## Существующие процессы watcher и ошибки запуска

Перед запуском watcher расширение запрашивает его текущее состояние у ядра.
Если lease проекта уже принадлежит другому терминалу, экземпляру редактора или
службе ОС, расширение принимает это состояние как внешний работающий watcher и
не запускает дубликат. Останавливать внешний watcher следует через владеющий им
процесс или службу.

Расширение периодически перепроверяет принятый watcher и, если он завершился,
перезапускает его при включённом auto-watch.

При ошибке запуска расширение сохраняет структурированное сообщение CLI,
записывает его в канал вывода **Symbraid** и показывает уведомление с действием
**Show Output**. То же сообщение доступно во всплывающей подсказке строки
состояния.
